# README — Exam3 (16 สิงหาคม) อธิบายโค้ดแบบละเอียดสุด ๆ

เอกสารนี้อธิบายโค้ดทุกไฟล์ ทุกฟังก์ชัน **ทีละบรรทัด** แบบที่ไม่ต้องมีพื้นฐาน
มาก่อนก็อ่านตามทันได้ เป้าหมายคือให้เอาไปตอบกรรมการตอนสอบปากเปล่าได้เลย

---

## 1. โจทย์คืออะไร (สรุป 1 นาที)

บอร์ดรอรับตัวอักษร 1 ตัวจากคอมพิวเตอร์ผ่านสาย UART (เหมือนพิมพ์ข้อความคุยกับบอร์ด)
แล้วตอบสนองตามตัวอักษรที่ส่งมา:

| ส่งอะไรไป | บอร์ดทำอะไร |
|---|---|
| `'0'` | ปิดไฟ LED 3 ดวง (น้ำเงิน แดง เหลือง) แล้วพิมพ์กลับมาว่า `OK` |
| `'1'` | เปิดไฟ LED 3 ดวง แล้วพิมพ์กลับมาว่า `OK` |
| `'t'` | พิมพ์อุณหภูมิปัจจุบัน เช่น `Temperature = 28400 millidegree Celcius` |
| `'l'` | พิมพ์ความสว่างปัจจุบัน เช่น `Light intensity = 144 Lux` |
| ตัวอื่น ๆ | พิมพ์ `Invalid Command` |

## 2. ปูพื้นก่อน — ศัพท์ที่ต้องรู้ก่อนอ่านโค้ด

ถ้าไม่รู้ 5 คำนี้ อ่านโค้ดข้างล่างจะงงมาก อ่านหัวข้อนี้ก่อน

### 2.1 Bit (บิต)
หน่วยข้อมูลเล็กที่สุด มีได้แค่ 2 ค่า คือ `0` กับ `1` — เหมือนสวิตช์ไฟที่มีแค่
"ปิด" กับ "เปิด" ตัวเลขในคอมพิวเตอร์ทุกตัวคือบิตหลาย ๆ ตัวเรียงกัน

### 2.2 Register (รีจิสเตอร์)
กล่องเก็บตัวเลขพิเศษที่ **อยู่ในตัวชิปจริง ๆ** (ไม่ใช่ตัวแปรธรรมดาในโปรแกรม)
แต่ละบิตในกล่องนี้ไปควบคุมฮาร์ดแวร์จริงของขา MCU เช่น ขาไหนเป็น input/output
ขาไหนมีไฟหรือไม่มีไฟ ในโค้ดเราจะเห็นแบบ `GPIOA->MODER` คือ "ไปเปิดกล่องชื่อ
MODER ของพอร์ต A" นั่นเอง

### 2.3 ตัวดำเนินการบิต (`&` `|` `~` `<<`)
โค้ดทุกไฟล์ในนี้ใช้ 4 ตัวนี้ซ้ำ ๆ ตลอด ต้องเข้าใจให้แม่น:

- **`|=` (OR แล้วเก็บ)** = "เปิด" บิตที่ต้องการ โดยไม่ไปยุ่งบิตอื่น
  เช่น `USART2->CR1 |= USART_CR1_TE;` = เปิดสวิตช์ TE เพิ่ม บิตอื่นในกล่องเดิม
  ไม่เปลี่ยน
- **`&= ~(...)` (AND กับตัวกลับบิต)** = "ปิด/เคลียร์" บิตที่ต้องการเป็น 0
  โดยไม่ไปยุ่งบิตอื่น เช่น `GPIOA->MODER &= ~(0x3u << (2u*2u));` = เคลียร์
  2 บิตที่ควบคุมขา PA2 ให้เป็น 0 ก่อน
- **`<<` (shift ซ้าย)** = เลื่อนตัวเลขไปทางซ้ายกี่บิต เช่น `1u << 5u` คือเอา
  เลข 1 (บิต 0000...0001) เลื่อนไปทางซ้าย 5 ตำแหน่ง กลายเป็น
  0000...0100000 (บิตที่ 5 ติด) ใช้เพื่อ "ชี้" ไปที่บิตตำแหน่งที่ต้องการ
  ของขา/ฟิลด์ที่ต้องการ

**ทำไมต้อง clear ก่อน set ทุกครั้ง?** เพราะ MODER แต่ละขาใช้ 2 บิต (ตั้งได้
4 ค่า: input/output/AF/analog) ถ้าค่าก่อนหน้าไม่ใช่ 00 แล้วเรา OR ค่าใหม่ทับ
ไปเลยโดยไม่เคลียร์ก่อน บิตเก่ากับใหม่จะปนกันได้ผลลัพธ์ผิด จึงต้อง "เคลียร์
เป็น 0 ก่อน แล้วค่อยตั้งค่าใหม่" เสมอ (เรียก pattern นี้ว่า clear-then-set)

### 2.4 MODER / ODR / IDR / AFR (รีจิสเตอร์ของ GPIO)
- **MODER** = ตั้งว่าขานี้ทำหน้าที่อะไร (00=Input, 01=Output, 10=Alternate
  Function, 11=Analog) ขาละ 2 บิต
- **ODR** (Output Data Register) = ค่าที่ "ส่งออก" ทางขา (ถ้าขาเป็น output)
  1 = ไฟติด (3.3V), 0 = ไฟดับ (0V) ขาละ 1 บิต
- **IDR** (Input Data Register) = ค่าที่ "อ่านเข้ามา" จากขา (ถ้าขาเป็น
  input) ขาละ 1 บิต — ใช้อ่านสถานะปุ่มกด/เซนเซอร์
- **AFR** (Alternate Function Register) = ถ้าตั้ง MODER เป็น 10 (AF) แล้ว
  ต้องมาบอกต่อว่า "AF เบอร์ไหน" ในนี้ เช่น UART, Timer แต่ละขาใช้ 4 บิต

### 2.5 ADC (Analog to Digital Converter)
วงจรแปลง **แรงดันไฟฟ้า (analog, ต่อเนื่อง 0-3.3V)** ให้เป็น **ตัวเลข
(digital, 0-4095 เพราะบอร์ดนี้ใช้ ADC 12 บิต = 2^12 = 4096 ระดับ)** ที่ CPU
เข้าใจได้ เช่น เซนเซอร์วัดอุณหภูมิจะออกมาเป็นแรงดันไฟฟ้า ต้องผ่าน ADC ก่อน
ถึงจะรู้ว่าตอนนี้กี่องศา

### 2.6 UART, Polling, Blocking
- **UART** = วิธีสื่อสารแบบส่งข้อมูลทีละบิตผ่านสายไฟ 2 เส้น (TX=ส่ง,
  RX=รับ) ใช้คุยกับคอมพิวเตอร์ผ่านพอร์ต Serial/USB
- **Polling** = "เช็คซ้ำ ๆ ในลูป" ว่าเหตุการณ์ที่รอเกิดขึ้นหรือยัง (ตรงข้าม
  กับ interrupt ที่ให้ฮาร์ดแวร์มาสะกิดเราเอง) โค้ดชุดนี้ **ไม่ใช้
  interrupt เลย** ใช้ polling ล้วน ๆ เพราะง่ายกว่า อธิบายง่ายกว่า
- **Blocking** = ฟังก์ชันที่ "หยุดค้าง" รอจนกว่าจะมีสิ่งที่ต้องการเกิดขึ้น
  ถึงจะทำงานต่อ (ตรงข้ามกับ non-blocking ที่เช็คแล้วคืนค่าทันทีไม่ว่าจะมี
  ข้อมูลหรือไม่) ฟังก์ชันรับข้อมูล UART ในโค้ดนี้เป็นแบบ blocking

## 3. โครงสร้างไฟล์ทั้งหมด

```
exam_3/
├── main.c            <- โปรแกรมหลัก อ่านคำสั่งแล้วสั่งงาน module อื่น
├── uart.c / uart.h   <- รับ-ส่งข้อมูลผ่านสาย UART (USART2)
├── led_control.c/.h  <- เปิด-ปิด LED 3 ดวงพร้อมกัน
└── sensor.c / sensor.h <- อ่านค่าอุณหภูมิ/ความสว่างผ่าน ADC
```

แต่ละไฟล์รับผิดชอบเรื่องเดียว (Single Responsibility) — `main.c` ไม่ไปยุ่ง
กับ register ของ UART/ADC โดยตรงเลย แค่เรียกฟังก์ชันของ module อื่นเท่านั้น

## 4. ภาพรวมการทำงานทั้งระบบ (flow)

```
เปิดบอร์ด
   │
   ▼
main() เริ่มทำงาน
   │
   ├─ clock_init()          เปิดไฟเลี้ยง (clock) ให้ GPIOA, USART2, ADC1
   ├─ uart_init()           ตั้งค่าขา PA2/PA3 ให้เป็น UART พร้อมรับ-ส่ง
   ├─ led_control_init()    ตั้งขา LED 3 ดวงเป็น output
   └─ sensor_init()         ตั้งขาเซนเซอร์เป็น analog, เปิด ADC
   │
   ▼
เข้าลูป while(1) วนตลอดไป ไม่มีวันออก
   │
   ├─▶ received_char = uart_receive_char()
   │      "ค้างรอตรงนี้" จนกว่าคอมพิวเตอร์จะส่งตัวอักษรมา
   │
   ├─▶ handle_command(received_char)
   │      เช็คว่าตัวอักษรที่ได้มาตรงกับคำสั่งไหนใน 4 คำสั่ง (switch-case)
   │      แล้วเรียกฟังก์ชันของ module ที่เกี่ยวข้อง + พิมพ์ผลลัพธ์กลับไป
   │
   └─▶ วนกลับไปรอรับตัวอักษรตัวถัดไป (กลับไปบรรทัดบนสุดของลูป)
```

**ทำไมไม่ต้องเช็ค flag หรือ interrupt เลย?** เพราะโปรแกรมนี้ไม่มีงานอื่น
ให้ทำระหว่างรอคำสั่งจากผู้ใช้เลย ขั้นตอน "ค้างรอ" (blocking) จึงไม่เสียหาย
อะไร ทำให้โค้ดเรียบง่ายมาก

## 5. เดินโค้ดทีละไฟล์ ทีละฟังก์ชัน

### 5.1 `main.c` — ศูนย์กลางควบคุม

```c
static void clock_init(void)
{
    RCC->AHB1ENR |= RCC_AHB1ENR_GPIOAEN;
    RCC->APB1ENR |= RCC_APB1ENR_USART2EN;
    RCC->APB2ENR |= RCC_APB2ENR_ADC1EN;
}
```
**อธิบาย:** ชิป STM32 จะ "ปิดไฟเลี้ยง" (clock) ของ peripheral ทุกตัวไว้ก่อน
ตอนเริ่มทำงาน เพื่อประหยัดพลังงาน ถ้าเราไม่เปิด clock ให้ peripheral ตัวไหน
ก่อน — ต่อให้ตั้งค่า register ของมันถูกทุกอย่าง มันก็จะไม่ทำงานเลย (ค่า
เขียนได้ปกติแต่ฮาร์ดแวร์จริงไม่ตอบสนอง) ฟังก์ชันนี้เปิดไฟเลี้ยงให้ครบ 3
peripheral ที่ต้องใช้: GPIOA (พอร์ตขา), USART2 (UART), ADC1

```c
static void handle_command(uint8_t command)
{
    switch (command)
    {
        case CMD_LED_OFF: ... break;
        case CMD_LED_ON:  ... break;
        case CMD_TEMP:    ... break;
        case CMD_LIGHT:   ... break;
        default:          ... break;
    }
}
```
**อธิบาย:** รับตัวอักษร 1 ตัว (ตัวแปร `command`) มาเทียบกับ 4 คำสั่งที่รู้จัก
ทีละอัน ถ้าตรงอันไหนก็ทำตามอันนั้น ถ้าไม่ตรงเลยสักอัน จะตกไปที่ `default`
โดยอัตโนมัติ (พิมพ์ "Invalid Command")

`CMD_LED_OFF` ฯลฯ คืออะไร? อยู่บนสุดของไฟล์:
```c
#define CMD_LED_OFF   ((uint8_t)'0')
#define CMD_LED_ON    ((uint8_t)'1')
#define CMD_TEMP      ((uint8_t)'t')
#define CMD_LIGHT     ((uint8_t)'l')
```
ตั้งชื่อให้ตัวอักษรแทนการเขียน `'0'`, `'1'` ลอย ๆ ในโค้ด อ่านแล้วรู้ทันที
ว่าหมายถึงคำสั่งอะไร (`CMD_TEMP` อ่านง่ายกว่า `'t'` เปล่า ๆ เยอะ)

```c
int main(void)
{
    uint8_t received_char;

    clock_init();
    uart_init();
    led_control_init();
    sensor_init();

    received_char = 0u;

    while (1)
    {
        received_char = uart_receive_char();
        handle_command(received_char);
    }

    return 0;
}
```
**อธิบายทีละบรรทัด:**
1. ประกาศตัวแปร `received_char` ไว้เก็บตัวอักษรที่รับมา
2. เรียก init 4 ฟังก์ชันเรียงกัน — เตรียมฮาร์ดแวร์ทุกตัวให้พร้อมก่อนเข้าลูป
3. `received_char = 0u;` ให้ค่าเริ่มต้นไว้ก่อน (กันไม่ให้เป็นค่าขยะก่อน
   ถูกเขียนทับ — MISRA บังคับห้ามใช้ตัวแปรก่อน initialize)
4. `while (1)` = ลูปไม่รู้จบ (โปรแกรมฝังตัวไม่มีวัน "จบโปรแกรม" เหมือน
   โปรแกรมทั่วไป มันวนรันตลอดไปจนกว่าจะปิดไฟ)
5. ในลูป: รอรับตัวอักษร แล้วเอาไปประมวลผล วนซ้ำไปเรื่อย ๆ

### 5.2 `uart.c` — รับ-ส่งข้อมูลผ่านสาย UART

#### `uart_init()` — เตรียมสาย UART ให้พร้อมใช้งาน

```c
GPIOA->MODER &= ~(0x3u << (2u * 2u));
GPIOA->MODER |= (0x2u << (2u * 2u));
```
ขา PA2 (ขาที่ 2 ของพอร์ต A) ปกติเป็น input พื้นฐาน เราต้องเปลี่ยนโหมดมันให้
เป็น **Alternate Function** (โหมด `10` = เลข `0x2u`) เพื่อให้ขานี้ทำหน้าที่
พิเศษ (เป็น UART TX) แทนที่จะเป็น GPIO ธรรมดา บรรทัดแรกเคลียร์ 2 บิตเดิม
ก่อน บรรทัดสองค่อยตั้งค่าใหม่ (clear-then-set ตามที่อธิบายไว้ข้อ 2.3)

```c
GPIOA->AFR[0] &= ~(0xFu << (2u * 4u));
GPIOA->AFR[0] |= (0x7u << (2u * 4u));
```
แค่บอกว่า "เป็น Alternate Function" ยังไม่พอ ต้องบอกต่อว่า "AF เบอร์ไหน"
— PA2 ต้องตั้งเป็น **AF7** ถึงจะกลายเป็น USART2_TX จริง ๆ (เลข AF ของ
UART/USART บนชิปตระกูลนี้คือ 7 เป็นค่ามาตรฐาน) จากนั้นทำแบบเดียวกันกับ PA3
(RX) อีกชุดข้างล่าง

```c
USART2->BRR = PCLK1_HZ / UART_BAUD_RATE;
```
**Baud rate** คือความเร็วในการส่งข้อมูล (หน่วย bit ต่อวินาที) ต้องตั้งให้
ตรงกับฝั่งคอมพิวเตอร์ (โปรแกรม terminal) ไม่งั้นข้อมูลจะกลายเป็นตัวอักษร
ขยะ สูตรอย่างง่ายคือ เอาความถี่สัญญาณนาฬิกาของ peripheral (`PCLK1_HZ` =
16,000,000 Hz ในที่นี้) มาหารด้วยความเร็วที่ต้องการ (`UART_BAUD_RATE` =
9600) ได้ค่าที่ต้องใส่ใน register `BRR`

```c
USART2->CR1 |= USART_CR1_TE;   /* เปิดฝั่งส่ง (Transmit Enable) */
USART2->CR1 |= USART_CR1_RE;   /* เปิดฝั่งรับ (Receive Enable) */
USART2->CR1 |= USART_CR1_UE;   /* เปิดการทำงานของ USART ทั้งตัว */
```
เปิด 3 สวิตช์ให้ครบ — **จุดพลาดที่พบบ่อยที่สุด** คือลืมเปิด `RE` แล้วบอร์ด
จะส่งข้อความออกได้ปกติ แต่รับคำสั่งจากคอมพิวเตอร์ไม่ได้เลย (เหมือนคนพูด
ได้แต่หูหนวก)

#### `uart_send_char()` — ส่งตัวอักษร 1 ตัว

```c
void uart_send_char(uint8_t data)
{
    while ((USART2->SR & USART_SR_TXE) == 0u)
    {
        /* รอจนกว่า TX buffer จะว่าง */
    }
    USART2->DR = data;
}
```
`TXE` (Transmit Empty) คือบิตที่บอกว่า "ช่องส่งข้อมูลว่างพร้อมรับตัวอักษร
ใหม่หรือยัง" ถ้ายังไม่ว่าง (แปลว่ากำลังส่งตัวอักษรก่อนหน้าอยู่) ฟังก์ชันนี้
จะวนรอเฉย ๆ ใน `while` (นี่คือ **polling** ตามข้อ 2.6) จนกว่าจะว่าง ถึงจะ
เขียนตัวอักษรใหม่ลงไปที่ `USART2->DR` ได้ ถ้าไม่รอแล้วเขียนทับตอนยังไม่ว่าง
ตัวอักษรเก่าที่ยังส่งไม่เสร็จจะหายไป

#### `uart_send_string()` — ส่งข้อความทั้งประโยค

```c
void uart_send_string(const char * str)
{
    uint32_t i;

    i = 0u;
    while (str[i] != '\0')
    {
        uart_send_char((uint8_t)str[i]);
        i = i + 1u;
    }
}
```
สตริงในภาษา C (เช่น `"OK"`) จริง ๆ แล้วคือ array ของตัวอักษร ที่ท้ายสุด
เก็บตัวอักษรพิเศษ `'\0'` (Null Terminator, ค่า 0) ไว้บอกว่า "จบข้อความ
แค่นี้" ฟังก์ชันนี้ไล่อ่านทีละตัวอักษรตั้งแต่ `str[0]` ไปเรื่อย ๆ ส่งออก
ทาง UART ทีละตัว จนกว่าจะเจอ `'\0'` ถึงจะหยุด

#### `uart_send_number()` — ส่งตัวเลขออกไปเป็นข้อความ (โจทย์ห้ามใช้ sprintf)

โจทย์ต้องพิมพ์ตัวเลขอย่าง `28400` ออกไป แต่ `28400` ในหน่วยความจำเป็น
**ตัวเลขจริง (binary)** ไม่ใช่ตัวอักษร ต้องแปลงเป็นตัวอักษร `'2'`,`'8'`,
`'4'`,`'0'`,`'0'` ก่อนถึงจะส่งออกทาง UART ได้ (เพราะ UART ส่งได้แค่ byte/
ตัวอักษร) ปกติภาษา C มีฟังก์ชัน `sprintf` ช่วยแปลงให้อัตโนมัติ แต่โจทย์
ข้อสอบ**ห้ามใช้** จึงต้องเขียนแปลงเอง:

```c
void uart_send_number(uint32_t number)
{
    uint8_t digit_buffer[MAX_DIGIT_COUNT];
    uint8_t digit_count;
    uint32_t remaining;

    digit_count = 0u;
    remaining = number;

    if (remaining == 0u)
    {
        uart_send_char((uint8_t)ASCII_DIGIT_ZERO);
    }
    else
    {
        while (remaining > 0u)
        {
            digit_buffer[digit_count] = (uint8_t)((remaining % DECIMAL_BASE) + ASCII_DIGIT_ZERO);
            remaining = remaining / DECIMAL_BASE;
            digit_count = digit_count + 1u;
        }

        while (digit_count > 0u)
        {
            digit_count = digit_count - 1u;
            uart_send_char(digit_buffer[digit_count]);
        }
    }
}
```

**หลักการ (สำคัญมาก ต้องอธิบายได้):** เอาเลข `28400` มาหาร 10 ไปเรื่อย ๆ
โดยเก็บ "เศษ" ที่ได้จากการหารแต่ละรอบไว้ — เศษที่ได้จะเป็น **หลักหน่วยก่อน
เสมอ** (ไม่ใช่หลักที่สูงสุด) ลองไล่ตามตัวอย่าง `number = 28400`:

| รอบ | `remaining % 10` (เศษ = 1 หลัก) | `remaining / 10` (ตัดหลักหน่วยทิ้ง) |
|---|---|---|
| 1 | 0 | 2840 |
| 2 | 0 | 284 |
| 3 | 4 | 28 |
| 4 | 8 | 2 |
| 5 | 2 | 0 (หยุด เพราะ `remaining` เป็น 0 แล้ว) |

จะเห็นว่า `digit_buffer` ถูกเติมเป็น `[0, 0, 4, 8, 2]` เรียงจาก **หลักหน่วย
ไปหาหลักสูงสุด** ซึ่งเป็นลำดับ "กลับหัว" จากที่คนอ่านต้องการ (คนอ่านอยากได้
`28400` ไล่จากหลักสูงสุดไปหลักหน่วย) ฟังก์ชันจึงมี **ลูปที่สอง** ไล่พิมพ์
จากท้าย buffer ย้อนไปหน้า (`digit_count` ลดลงเรื่อย ๆ) เพื่อพิมพ์ออกมาเป็น
`"28400"` ที่ถูกลำดับ

`(remaining % 10) + ASCII_DIGIT_ZERO` คืออะไร? ตัวเลข `0` เป็นตัวอักษรใน
คอมพิวเตอร์ (ASCII) มีรหัสเป็น `48` ไม่ใช่ `0` ตัวเลขล้วน ๆ — ถ้าอยากได้
ตัวอักษร `'4'` (รหัส ASCII = 52) จากตัวเลข `4` ต้องเอา `4 + 48 = 52` พอดี
โค้ดจึงบวก `ASCII_DIGIT_ZERO` (=48) เข้าไปเสมอเพื่อแปลง "เลขจริง" เป็น
"ตัวอักษรของเลขนั้น"

**กรณีพิเศษ:** ถ้า `number` เป็น `0` ตั้งแต่แรก ลูป `while (remaining > 0u)`
จะไม่ทำงานเลยสักครั้ง (เพราะเงื่อนไขเป็นเท็จตั้งแต่ต้น) ผลคือไม่พิมพ์อะไร
เลยทั้งที่ควรพิมพ์ `"0"` — โค้ดจึงมี `if (remaining == 0u)` ดักไว้ก่อนเป็น
กรณีพิเศษ

#### `uart_receive_char()` — รอรับตัวอักษร 1 ตัว (แบบ blocking)

```c
uint8_t uart_receive_char(void)
{
    while ((USART2->SR & USART_SR_RXNE) == 0u)
    {
        /* รอจนกว่าจะมีข้อมูลเข้ามา */
    }
    return (uint8_t)USART2->DR;
}
```
`RXNE` (Receive Not Empty) คือบิตที่บอกว่า "มีข้อมูลเข้ามาในช่องรับหรือยัง"
ถ้ายังไม่มี (เป็น 0) ฟังก์ชันจะวนรออยู่ตรงนี้ **ค้างไม่ไปไหน** จนกว่าจะมี
ตัวอักษรเข้ามาจริง ๆ (คนพิมพ์คำสั่งส่งเข้ามาทาง terminal) — นี่คือที่มาของ
คำว่า "blocking" ตามข้อ 2.6 พอมีข้อมูลเข้ามา อ่านค่าจาก `USART2->DR` แล้ว
`return` กลับไป (การอ่าน `DR` จะเคลียร์ `RXNE` ให้อัตโนมัติด้วย ไม่ต้อง
เคลียร์เอง)

### 5.3 `led_control.c` — เปิด/ปิด LED 3 ดวงพร้อมกัน

```c
#define LED_BLUE_PIN         (5u)   /* PA5 = D13 = น้ำเงิน */
#define LED_RED_PIN          (6u)   /* PA6 = D12 = แดง */
#define LED_YELLOW_PIN       (7u)   /* PA7 = D11 = เหลือง */
```
ตั้งชื่อขาให้จำง่าย — แทนที่จะเขียน `5u` ลอย ๆ ทั่วไฟล์ (แล้วต้องมานั่งจำ
เองว่า 5 คือ LED สีอะไร) ใช้ชื่อที่สื่อความหมายแทน

```c
void led_control_init(void)
{
    GPIOA->MODER &= ~(GPIO_MODER_MASK << (LED_BLUE_PIN * GPIO_MODER_PIN_BITS));
    GPIOA->MODER |= (GPIO_MODER_OUTPUT << (LED_BLUE_PIN * GPIO_MODER_PIN_BITS));
    ... (ทำซ้ำแบบเดียวกันกับ RED, YELLOW)
}
```
ตั้งขา LED ทั้ง 3 เป็นโหมด **Output** (`01`) เหมือนหลักการเดียวกับ UART ใน
ข้อ 5.2 (clear 2 บิตเดิมก่อน แล้วค่อยตั้งใหม่) เพื่อให้ขานี้ "จ่ายไฟออก" ได้
(ถ้าไม่ตั้งเป็น output ขาจะยังเป็น input โดยปริยาย เขียน `ODR` เท่าไหร่ก็
ไม่มีผลกับ LED จริง)

```c
void led_all_on(void)
{
    GPIOA->ODR |= (1u << LED_BLUE_PIN);
    GPIOA->ODR |= (1u << LED_RED_PIN);
    GPIOA->ODR |= (1u << LED_YELLOW_PIN);
}

void led_all_off(void)
{
    GPIOA->ODR &= ~(1u << LED_BLUE_PIN);
    GPIOA->ODR &= ~(1u << LED_RED_PIN);
    GPIOA->ODR &= ~(1u << LED_YELLOW_PIN);
}
```
`led_all_on()`: OR บิตของ LED ทั้ง 3 ให้เป็น 1 → ไฟติดพร้อมกันทั้ง 3 ดวง
`led_all_off()`: AND กับตัวกลับบิตของ LED ทั้ง 3 ให้เป็น 0 → ไฟดับทั้ง 3
ดวง (หลักการ set/clear บิตเดียวกับที่อธิบายในข้อ 2.3 เป๊ะ ๆ)

### 5.4 `sensor.c` — อ่านค่าอุณหภูมิ/ความสว่างผ่าน ADC

> **ข้อสมมติที่ใช้ในไฟล์นี้ (สำคัญ ต้องรู้ไว้ตอบกรรมการ):** เนื่องจากโจทย์
> ไม่ได้ระบุเซนเซอร์ที่ใช้จริง โค้ดนี้จึงสมมติว่า
> - อุณหภูมิอ่านจาก **PA1 (A1, ADC channel 1)** เป็นเซนเซอร์แบบ **LM35**
>   (ให้แรงดันออกมา 10mV ต่อ 1 องศาเซลเซียส)
> - ความสว่างอ่านจาก **PA4 (A2, ADC channel 4)** เป็น LDR แปลงค่าดิบเป็น
>   Lux ด้วยสูตรเชิงเส้นอย่างง่าย (`lux = adc_raw / 10`)
>
> ถ้าฮาร์ดแวร์จริงในห้องสอบใช้ขาอื่นหรือเซนเซอร์อื่น ต้องแก้ค่าพวกนี้ให้
> ตรงก่อนใช้จริง

#### `sensor_init()` — เตรียม ADC ให้พร้อมอ่านค่า

```c
GPIOA->MODER &= ~(0x3u << (1u * 2u));
GPIOA->MODER |= (0x3u << (1u * 2u));
```
ตั้งขา PA1 เป็นโหมด **Analog** (`11` = เลข `0x3u`) — ขาที่จะใช้กับ ADC ต้อง
ตั้งเป็นโหมดนี้เท่านั้น (ไม่ใช่ input/output ธรรมดา) เพื่อให้วงจร ADC เข้าถึง
แรงดันไฟฟ้าจริงบนขานั้นได้ตรง ๆ ไม่ผ่านวงจร digital ที่จะรบกวนค่า จากนั้น
ทำแบบเดียวกันกับ PA4

```c
ADC1->SMPR2 |= ADC_SMPR2_SMP1;
ADC1->SMPR2 |= ADC_SMPR2_SMP4;
```
**Sample Time** คือเวลาที่ ADC ใช้ "จับ" แรงดันไฟฟ้าก่อนเริ่มแปลงค่า ยิ่งตั้ง
นานยิ่งแม่นยำ (เหมาะกับแหล่งสัญญาณที่มี impedance สูง) — บรรทัดนี้ตั้ง
sample time ให้ channel 1 (อุณหภูมิ) กับ channel 4 (ความสว่าง) ไว้ล่วงหน้า
ทั้งคู่ (ตั้งครั้งเดียวใน init ใช้ได้ตลอด ไม่ต้องตั้งใหม่ทุกครั้งที่อ่าน)

```c
ADC1->CR2 |= ADC_CR2_ADON;
```
เปิดสวิตช์ใหญ่ให้ ADC เริ่มทำงาน (Analog-to-Digital ON)

#### `sensor_read_temperature_millidegc()` — อ่านอุณหภูมิ

```c
uint32_t sensor_read_temperature_millidegc(void)
{
    uint16_t adc_raw;
    uint32_t millivolt;
    uint32_t millidegc;

    adc_raw = adc_convert_channel(TEMP_CHANNEL);
    millivolt = ((uint32_t)adc_raw * ADC_VREF_MILLIVOLT) / ADC_MAX_VALUE;
    millidegc = millivolt * LM35_MILLIVOLT_TO_MILLIDEGC;

    return millidegc;
}
```
**ขั้นตอนที่ 1:** เรียก `adc_convert_channel(1)` ไปอ่านค่าดิบจาก ADC channel
1 (PA1) ได้ตัวเลข 0-4095 กลับมา (สมมติได้ `353`)

**ขั้นตอนที่ 2 — แปลงค่าดิบเป็นแรงดันไฟฟ้า (mV):**
```
millivolt = (adc_raw × 3300) / 4095
```
ADC วัดค่าได้ 0-4095 ระดับ เทียบกับแรงดันอ้างอิง (VREF) เต็มสเกล 3300mV
(3.3V) — เอาสัดส่วนมาคูณกันเพื่อแปลงกลับเป็นแรงดันจริง ตัวอย่าง:
`(353 × 3300) / 4095 ≈ 284 mV`

**ขั้นตอนที่ 3 — แปลงแรงดันเป็นอุณหภูมิ (ตามสเปก LM35):**
LM35 ให้ 10mV ต่อ 1 องศา หมายความว่า `1 mV = 100 millidegree Celsius`
(เพราะ `10mV = 1000 millidegree`, หาร 10 ได้ `1mV = 100 millidegree`)
```
millidegc = millivolt × 100
```
ตัวอย่าง: `284 × 100 = 28400 millidegree Celsius` (= 28.4°C)

**ทำไมคูณก่อนหารเสมอ ไม่หารก่อนคูณ?** เพราะตัวแปรเป็นจำนวนเต็ม (integer)
ไม่มีจุดทศนิยม ถ้าหารก่อนจะเสียเศษทิ้งไปตั้งแต่ขั้นแรก ทำให้ผลลัพธ์สุดท้าย
คลาดเคลื่อนมากกว่าคูณก่อนแล้วค่อยหารทีเดียว (integer truncation)

#### `sensor_read_light_lux()` — อ่านความสว่าง

```c
uint32_t sensor_read_light_lux(void)
{
    uint16_t adc_raw;
    uint32_t lux;

    adc_raw = adc_convert_channel(LIGHT_CHANNEL);
    lux = (uint32_t)adc_raw / LDR_LUX_SCALE_DIVISOR;

    return lux;
}
```
อ่านค่าดิบจาก channel 4 (PA4) แล้วหารด้วย 10 ตรง ๆ (สูตรประมาณอย่างง่าย
เพราะความสัมพันธ์จริงของ LDR กับความสว่างไม่เป็นเส้นตรง แต่โจทย์เน้นความ
ง่ายในการอธิบาย จึงใช้สูตรเชิงเส้นแทน)

#### `adc_convert_channel()` — ฟังก์ชันกลางที่ใช้อ่านค่า ADC จริง ๆ

```c
static uint16_t adc_convert_channel(uint8_t channel)
{
    ADC1->SQR3 &= ~ADC_SQR3_SQ1;
    ADC1->SQR3 |= ((uint32_t)channel << ADC_SQR3_SQ1_Pos);

    ADC1->CR2 |= ADC_CR2_SWSTART;

    while ((ADC1->SR & ADC_SR_EOC) == 0u)
    {
        /* รอแปลงเสร็จ */
    }

    return (uint16_t)ADC1->DR;
}
```
ฟังก์ชันนี้ **ใช้ร่วมกันทั้งอุณหภูมิและความสว่าง** (ถูกเรียก 2 จุด ต่างกัน
แค่พารามิเตอร์ `channel`) เพราะ ADC1 บนชิปนี้มีตัวเดียว แต่ต้องอ่านได้ทั้ง
2 ขา จึงต้อง "สลับ channel" ก่อนอ่านทุกครั้ง:

1. `SQR3` (Sequence Register) บอก ADC ว่า "ลำดับที่ 1 จะให้อ่าน channel
   ไหน" — เคลียร์ค่าเดิมก่อน แล้วใส่เลข channel ใหม่ที่รับมาทาง
   พารามิเตอร์
2. `SWSTART` (Software Start) = สั่งให้เริ่มแปลงค่าเดี๋ยวนี้
3. `EOC` (End Of Conversion) = บิตที่บอกว่า "แปลงเสร็จหรือยัง" วนรอ
   (polling) จนกว่าจะติด
4. อ่านค่าที่แปลงเสร็จแล้วจาก `ADC1->DR` แล้ว `return` กลับไป

## 6. ตัวอย่างการรันจริง — ส่ง `'t'` เข้าไปเกิดอะไรขึ้นบ้าง (ไล่ทีละสเต็ป)

```
1. บอร์ดวนอยู่ใน while(1) ค้างที่ uart_receive_char() รอรับตัวอักษร
2. ผู้ใช้พิมพ์ 't' ใน terminal แล้วกด Enter (หรือ terminal ส่งทันทีที่พิมพ์)
3. ฮาร์ดแวร์ USART2 รับบิตข้อมูลมาจนครบ 1 ตัวอักษร -> ตั้งบิต RXNE = 1
4. uart_receive_char() หลุดจาก while รออ่านค่าจาก USART2->DR ได้ 't' (0x74)
   -> return (uint8_t)0x74 กลับไปที่ main()
5. received_char = 0x74
6. handle_command(0x74) ถูกเรียก
7. switch เทียบ 0x74 กับ CMD_LED_OFF('0'=0x30) ไม่ตรง
   เทียบกับ CMD_LED_ON('1'=0x31) ไม่ตรง
   เทียบกับ CMD_TEMP('t'=0x74) ตรง! เข้า case นี้
8. uart_send_string("Temperature = ")  -> พิมพ์ 14 ตัวอักษรออกไปทีละตัว
9. sensor_read_temperature_millidegc() ถูกเรียก:
   a. adc_convert_channel(1) เลือก channel 1, สั่งแปลง, รอ EOC,
      อ่านได้ค่าดิบสมมติ = 353
   b. millivolt = (353 * 3300) / 4095 = 284
   c. millidegc = 284 * 100 = 28400
   d. return 28400
10. uart_send_number(28400) ถูกเรียก:
    a. แตกหลัก: เศษที่ได้ตามลำดับคือ 0,0,4,8,2 (หลักหน่วยก่อน)
    b. พิมพ์ย้อนกลับจากท้าย buffer: '2' '8' '4' '0' '0'
    c. คนอ่านเห็นข้อความ "28400" ต่อจาก "Temperature = "
11. uart_send_string(" millidegree Celcius\n") -> พิมพ์ต่อท้ายจนจบบรรทัด
12. handle_command() จบการทำงาน กลับไปที่ main()
13. วนกลับไปเรียก uart_receive_char() ใหม่ รอตัวอักษรตัวถัดไป
```

ผลลัพธ์สุดท้ายที่เห็นบนหน้าจอ terminal:
```
Temperature = 28400 millidegree Celcius
```

## 7. สรุปย่อ (ท่องก่อนเข้าห้องสอบ)

> โปรแกรมนี้วนลูป `while(1)` รอรับตัวอักษร 1 ตัวจาก UART แบบ **blocking**
> (ค้างรอ ไม่ใช้ interrupt) พอได้ตัวอักษรมาก็ส่งเข้า `switch-case` เทียบกับ
> 4 คำสั่งที่รู้จัก (`'0'`, `'1'`, `'t'`, `'l'`) ถ้าไม่ตรงสักอันจะพิมพ์
> "Invalid Command" โดยอัตโนมัติผ่าน `default` คำสั่งเปิด/ปิด LED เขียน
> ค่าตรง ๆ ลง `ODR` ส่วนคำสั่งอ่านค่าเซนเซอร์ต้องสั่ง ADC ให้แปลงค่าก่อน
> (`SWSTART` → รอ `EOC` → อ่าน `DR`) แล้วแปลงตัวเลขดิบเป็นหน่วยจริงด้วย
> สูตรคูณ-หารจำนวนเต็ม สุดท้ายแปลงตัวเลขเป็นข้อความเองทีละหลัก (ห้ามใช้
> `sprintf`) ด้วยการหาร/มอด 10 วนไปเรื่อย ๆ แล้วพิมพ์ย้อนกลับ

## 8. คำถามที่กรรมการอาจถาม + คำตอบเตรียมไว้

**Q: ทำไมไม่ใช้ interrupt รับ UART?**
A: โปรแกรมนี้ไม่มีงานอื่นให้ทำระหว่างรอคำสั่งเลย การ block รอในลูปจึงไม่
เสียหายอะไร และทำให้โค้ดเข้าใจง่ายกว่าการเขียน interrupt + flag

**Q: ทำไมต้องเคลียร์บิตก่อนตั้งค่าใหม่ทุกครั้ง (`&= ~(...)` ก่อน `|= `)?**
A: เพราะ field พวกนี้ (เช่น MODER 2 บิต/ขา) ค่าจากรีเซ็ตหรือค่าตั้งไว้ก่อน
หน้าอาจไม่ใช่ 0 ถ้า OR ทับไปตรง ๆ โดยไม่เคลียร์ก่อน บิตเก่ากับใหม่จะปนกัน
ได้ค่าที่ไม่ตรงกับที่ตั้งใจ

**Q: ทำไมห้ามใช้ sprintf แล้วทำยังไงแทน?**
A: แปลงตัวเลขเป็นตัวอักษรเองด้วยการหารด้วย 10 ไปเรื่อย ๆ เก็บเศษที่ได้
(หลักหน่วยก่อนเสมอ) ใส่ buffer แล้วพิมพ์ย้อนกลับจากท้าย buffer มาหน้า

**Q: ทำไมตัวแปร ADC ต้องเป็น `uint16_t` ไม่ใช่ `uint8_t`?**
A: ADC ของบอร์ดนี้คือ 12 บิต ค่าที่ได้มีตั้งแต่ 0-4095 ซึ่งเกินขอบเขตของ
`uint8_t` (0-255) ต้องใช้ `uint16_t` (0-65535) ถึงจะเก็บได้ครบ

**Q: `adc_convert_channel()` ทำไมใช้ฟังก์ชันเดียวกันทั้งอุณหภูมิ/ความสว่าง?**
A: ชิปนี้มี ADC1 อยู่ตัวเดียว ต้องอ่านสลับ 2 channel จึงรวม logic "เลือก
channel → สั่งแปลง → รอเสร็จ → อ่านค่า" ไว้ในฟังก์ชันเดียว ส่งแค่เลข
channel เข้าไปต่างกัน ลดการเขียนโค้ดซ้ำ
